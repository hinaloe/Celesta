# React 19 across the workspace (2026-10-14)

The runtime packages, templates, and examples were on React 18
(`react-reconciler` 0.29) while `packages/website` and `packages/logos`
were on React 19. Every workspace package now uses `react` and
`@types/react` `^19.3.0`, and `@celesta/react` uses `react-reconciler` and
`@types/react-reconciler` `^0.34.0`. The lockfile holds one `react`
(19.3.0). `examples/versus/bench/remotion` is outside the workspace and
keeps the React that its Remotion version pins.

- Host config (`packages/react/src/reconciler.ts`): `prepareUpdate` is gone
  and `commitUpdate(instance, type, oldProps, newProps)` runs whenever the
  props object changes, so the `sameProps` check moved into it. It still
  leaves the node untouched when the values are equal, which keeps a
  `<Static>` from looking changed every frame. `getCurrentEventPriority` is
  replaced by the `set`/`get`/`resolveUpdatePriority` triple, and the
  commit-suspension, transition, form, and DevTools entries 0.34 reads are
  no-ops. `commitUpdate` takes the fiber as its fifth argument, and the
  node keeps it for `sourceChain` only when the props change, as it did
  when `prepareUpdate` skipped the commit.
- Layer sources: `@celesta/react/jsx-dev-runtime` keys positions by the
  element's props object, not by React's `_debugSource`, which React 19
  removed. Fibers still carry that object as `memoizedProps`, so
  `sourceChain` works unchanged.
- Root: 0.34 has no legacy mode (`createContainer` makes every root
  concurrent), so the root is created as `ConcurrentRoot`. `createRoot()`
  now returns `render(element)`, which runs `updateContainerSync` and
  `flushSyncWork`. Sync-lane passive effects are flushed during the
  commit, so `useEffect` runs before `render` returns. Under the legacy
  root it ran later, from the scheduler.
- Errors: React 19 no longer rethrows an uncaught render error from the
  update. It passes the error to `onUncaughtError` during the commit, and
  anything that callback throws is rethrown from a `setTimeout`, which
  would kill the process. The callback stores the error, and `render`
  throws it after the commit. That keeps the "could not render the
  composition: …" errors and the throwing tests in `packages/cli/test`.
  Errors that an error boundary caught, and recoverable errors, go to
  `console.error`. A component that throws still renders three times in
  the failing update in the development build, as it did under React 18's
  legacy root. React's "The above error occurred in the <X> component"
  message and its component stack are no longer printed to stderr, because
  the root's `onUncaughtError` replaces the default that logged them.
- Console (`packages/cli/src/cli.ts`): the `Console` that routes output
  to stderr lacks the global console's inspector-only methods. React 19's
  development build calls `console.timeStamp` on every render, so every
  frame failed with `console.timeStamp is not a function`. The routed
  console now inherits from the global one, so those methods (which write
  to neither stream) are still there.
- Types: React 19's `createRef<T>()` and `useRef<T>(null)` return
  `RefObject<T | null>`, and `RefObject<T>`'s `current` is no longer
  nullable. `AssetInput` accepts `RefObject<AssetReference | null>`, and
  `templates/dialogue` declares its refs that way. Compositions that
  declare `RefObject<AssetReference>` for a `createRef` need the same
  change.

## Checks

On macOS 26.7.1 with Node 26.10.0:

- `pnpm run build` (all 19 turbo tasks) and `pnpm run test:runtime` (every
  runtime package, `packages/cli` included) pass, and their output has no
  React warnings. `templates` `typecheck` and `test` pass, and
  `scripts/typecheck-examples.mjs` passes for the four examples with a
  `tsconfig.json`. The other examples, checked through a temporary
  `tsconfig.json`, show only errors that do not involve React (`lib`
  targets, `unknown` values, the Remotion bench's missing modules).
- `cargo test -p celesta-react-bridge -p celesta-exporter -p celesta-mcp`
  passes, with no ignored tests.
- Render comparison: about 12 evenly spaced frames of every
  `examples/*/film*.tsx`, `templates/*/film.tsx`, and
  `packages/cli/examples/*.tsx` (601 PNGs, with
  `examples/minimal.celesta.json` as the companion project for the
  three project entries) were exported with `celesta-exporter --react
  --every N`. One exporter built from this branch rendered them twice. In
  one run, the `runtime/` directory beside it pointed at `main`'s React 18
  runtime, and in the other at this branch's React 19 runtime. The PNGs are
  byte-identical, as were two React 18 runs of the same frames. The
  entries that failed with both runtimes fail only for media that is not
  in Git: generated voices, `.wav`/`.mp4` files, `teto.psd`, and
  `character.png`. `static-scene.tsx` has no default export.
  `shorts-explainer` names a different missing voice file each time,
  because `prepareVoices()` reads them in parallel.
- MP4 export of `templates/dialogue` and `examples/rich-text` succeeds.
