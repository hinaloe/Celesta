# Lottie animations (2026-10-19)

Issue #309. `<Lottie>` in the new `@celesta/lottie` package plays a Lottie
(Bodymovin) JSON export in step with the composition.

```tsx
import { Lottie } from '@celesta/lottie';
import confetti from './confetti.json';

<Lottie data={confetti} x={960} y={540} anchorX={0.5} anchorY={0.5} width={800} />
```

- No new renderer primitive. Each frame, the component evaluates the file at
  that frame in TypeScript and returns `<Group>`s, `<Path>`s, `<Rect>`s,
  `<Image>`s, and `<Mask>`s, so preview, export, and `@celesta/web` draw
  it as they draw any scene, and a frame depends only on its time
  (scrubbing equals playing). A skewed Lottie layer is a skewed group, which
  the CPU reference renderer refuses as it refuses any skew.
- Timing follows lottie-web: a layer shows while `ip ≤ frame < op` (the
  composition's frames); its properties are read at `frame − st`; a
  precomposition's layers at that frame over `sr`, or at its time remap
  (`tm`, seconds × `fr`, with lottie-web's `op → op − 1` quirk). Playback
  maps `seconds × playbackRate × fr` into `[startFrame, endFrame)`
  (defaults `ip`/`op`), wrapping with `loop` (default) or holding
  `endFrame − 1`, as lottie-web stops (`lottieFrameAt`). Frames between the
  file's interpolate (lottie-web's subframe rendering).
- Properties (`property.ts`): keyframes with per-dimension Bézier easing,
  hold keyframes, old `e` end values, spatial position curves (`to`/`ti`,
  moved at even speed along 150 samples of the curve), split positions,
  and path morphing vertex by vertex.
- Transforms (`geometry.ts`): position · rotation · skew · scale · −anchor,
  skew along its axis as `R(−sa) · shearX(−sk) · R(sa)` like lottie-web's
  `skewFromAxis`. A layer's matrix, with its parents', is decomposed into
  `<Group>` props `x`/`y`/`rotation`/`skewX`/`scaleX`/`scaleY`
  (`R · K · S`, the order `EvaluatedTransform::linear` composes); a matrix
  with no area draws nothing. Parent opacity is not inherited.
- Shapes (`shapes.ts`): a group's items are read top first; each paint draws
  every path before it in the group, nested groups' paths included through
  their transforms; paints listed later draw underneath. Rectangles,
  ellipses, and stars/polygons start and turn as lottie-web builds them
  (rect from its top-right corner, ellipse from its top, `d: 3` reversed),
  so trim paths match. Trim paths (`trimPath`, newly exported from
  `@celesta/shapes`) cut the paths before them, fills included: start/end
  turned by the offset, wrapping as two ranges, per path (simultaneously)
  or over all of them as one length (individually). Gradients merge their
  color and opacity stops into `#RRGGBBAA` stops.
- Masks (`layers.ts`): combined in order as nested groups: add joins the
  mask's drawing, subtract masks the result with the mask inverted,
  intersect masks it with the mask. A first mask that subtracts or
  intersects starts from the whole layer, drawn as the composition's box
  mapped back into layer space (bounded, unlike an "infinite" rect).
  Inverted masks and mask opacity are honoured. Track mattes (`tt` 1–4,
  with `tp` or the layer above) become `<Group mask={<Mask mode invert>}>`.
- Precompositions and the root box clip to their `w`/`h`, as lottie-web's
  SVG renderer does. Image layers load `assetsPath` + `p` (default the
  asset's `u`), relative to the entry.
- Not drawn, reported once per file and handler through `onWarning`
  (default `console.warn`, which reaches the bridge's stderr), and by
  `inspectLottie(data)`: text, audio, camera, and other layer types,
  expressions, effects, layer styles, 3D, auto-orient, merge paths,
  repeaters, round corners, pucker/twist/offset/zig-zag, the even-odd fill
  rule (paths fill non-zero only), radial highlights, lighten/darken/
  difference masks, mask expansion, and embedded images (the native
  renderers do not read data URLs).
- Wiring: `@celesta/cli` depends on the package (the runtime and `.celesta`
  types pick it up from there), and `@celesta/web`'s worker serves it
  (`runtimeModules`, `engine.worker.ts`).

Validation: `packages/lottie/test/evaluate.test.mjs` (easing, keyframes,
spatial positions, path morphing, transform decomposition, shape start
points, trim ranges, timing, `inspectLottie`) and `render.test.mjs` (through
the CLI: scrubbing out of order equals playing, loop and hold, the box and
clip, masks/mattes/precomps/gradients, trim, warnings, bad data);
`packages/web/test/engine-worker.test.mjs` compiles and draws the demo in
the worker. `packages/cli/examples/with-lottie.tsx` plays
`examples/assets/lottie/demo.json` (trimmed ring on a parented null, a star
on a curved motion path, bars in a precomposition revealed by a track matte,
a solid cut by add and subtract masks). Its frames exported with
`celesta-exporter` matched lottie-web 5.12.2's SVG renderer at the same
frames by eye.
