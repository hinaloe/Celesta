# Project templates and `props.json` (2026-10-11)

Sub-project 1 of 2. `celesta-editor --init` can start from a ready-made
template, and a project's `props.json` reaches the preview and the exporter
without command-line options. The design is
`docs/superpowers/specs/2026-10-11-project-templates-design.md`; sub-project 2
(editing properties in the Inspector, writing back to `props.json`) is not
started.

## Interface

- `celesta-editor --init [DIR] --template NAME` initializes from a template.
  Without `--template` the result is exactly the old starter (`blank`).
  `--template` requires `--init`. An unknown name fails with exit status 1
  and the available names before anything is written. After the usual message
  the template's `edit` line is printed.
- `celesta-editor --list-templates` prints `name  title — description` per
  template and exits; it conflicts with `PROJECT`, `--init`, and the property
  options.
- GUI: **File > Create New Project…** shows a template chooser (gpui-kit
  dialog, Blank selected, Enter confirms, Escape cancels) before the folder
  picker. A conflict or missing runtime templates appears in `open_error` as
  `Couldn’t create project: …`.
- Existing files: without `--template`, `.celesta/` is refreshed and missing
  starter files are created from `blank`; existing files are kept. With
  `--template`, any file the template would create that already exists
  aborts the whole initialization and every conflicting path is listed;
  nothing is written. `package.json`, `tsconfig.json`, and `.gitignore` are
  kept when present in both cases.

## Templates

`templates/{blank,slideshow,ranking,dialogue}/`, each with `template.json`
(`title`, `description`, `edit`; not copied). All but `blank` declare
`format` (`16:9` / `9:16`, 1920×1080 / 1080×1920, 30 fps), ship a
`props.json` and a data file (`slides.json`, `data.json`, `script.json`), and
a `README.md`. Duration follows the data. Text is Noto Sans JP via `<Font>`
(downloaded on first use).

- `blank`: the old `crates/react-bridge/templates/film.tsx`, no `props.json`.
- `slideshow`: title card, `<TransitionSeries>` of `<Image fit="cover">`
  slides with pan/zoom and captions, optional music. Sample photos and the
  music loop are generated by the scripts in `templates/slideshow/source/`,
  which is not copied into projects.
- `ranking`: moved from `examples/ranking` (removed); gained `format`; the
  variants in `variants/` remain the `--props-file` example.
- `dialogue`: `script.json` carries the cast and the lines. `voice` is
  optional by user decision: lines without one are timed from text length
  (`MIN_LINE_SECONDS` 1.5, `SECONDS_PER_CHAR` 0.15) with the mouth moving
  through the vowels of `reading`. The sample ships without voices.

## Distribution

`packages/cli/scripts/stage-templates.mjs` runs in `@celesta/cli`'s `build`
after `stage-project-types.mjs` and copies `templates/<name>/` into
`packages/cli/dist/templates/<name>/`, leaving out the top-level `source/`.
`stage-react-runtime.mjs` already copies all of `dist/`, so packaged apps ship
the templates unchanged. `.gitignore` has `!templates/*/assets/**` so sample
media is tracked.

Rust: `crates/react-bridge/src/project_templates.rs` has `list_templates`,
the conflict check, and the recursive copy (skipping `template.json`);
`initialize_project(cli_script, root, Option<&str>)` uses it, and
`project_types.rs` keeps only `.celesta/` management. The `include_str!`
starter is gone.

## `props.json` next to the entry

An entry opened or exported without `--props-file`, with a `props.json` in
its own folder (not an ancestor), loads it as a property layer with source
`entryProps`. `--props-file` replaces it; `--props` wins over both.

Precedence, highest first:

1. `--props`
2. `--props-file`, or else the entry's `props.json`
3. the `--project` companion file's `properties`
4. the nearest `<ProjectProvider>` (only `useProjectProperty`)
5. the declared `defaultValue`
6. the hook's or function's `defaultValue` argument

Strictness (`packages/cli/src/property-inputs.ts`): when the entry declares
properties, `entryProps` is checked like `--props-file` (undeclared keys,
types, colors, path existence, reported as `invalidProperties` with source
`entryProps`); when it declares none the layer is ignored with a warning;
malformed JSON or a non-object is an error regardless.

Plumbing: `PropertyInputs::load_for_entry(entry, props_file, props)` does the
discovery for the editor, the exporter, and `skills/celesta/scripts/inspect.mjs`
(same rule in JavaScript). The editor rediscovers on every reload and its
reload watcher includes the existence and mtime of `<entry dir>/props.json`;
the React Preview panel lists `props.json (auto)`. The exporter dashboard
shows ` Props    props.json (auto)`, and `--json` reports `propsFile` and
`propsFileAuto`.

## Tests

```sh
pnpm run build:runtime            # also stages dist/templates
pnpm run test:runtime
pnpm --dir templates test         # CI runs this; also: pnpm --dir templates typecheck
cargo test --workspace            # PKG_CONFIG_PATH must point at ffmpeg@8
```

`templates/test/` evaluates every template with its own `props.json` in both
formats (module load, validation, `prepare()`, size/fps/duration) and checks
that staging produced `dist/templates/<name>/template.json` without
`source/`. Rendering happens in Rust, so no font download is needed.

## Verification

Run with release builds of `celesta-editor` and `celesta-exporter`:
`--init <scratch>/<name> --template <name>`, then
`--react --every 30 --contact-sheet --props '{"format":"…"}'` for both
formats. All six sheets were read; nothing was clipped, and every caption and
portrait stayed inside the frame.

- slideshow 16:9: dark title card fades in with title, rule, and subtitle; five
  scenes (harbor, mountains, lake, dusk, night) cross-fade with captions at the
  lower left; 590 frames.
- slideshow 9:16: the same, photos cropped to portrait; captions larger and
  inside the frame.
- ranking 16:9: title and subtitle with a blue accent bar, three rows with
  bars growing; values count up to 1,200 / 960 / 720; 153 frames.
- ranking 9:16: the same stacked vertically with larger type, centered with
  empty space above and below; nothing clipped.
- dialogue 16:9: the two portraits side by side, title across the top, a
  speaker-colored subtitle band along the bottom with the name tag, mouths
  changing between frames; 678 frames.
- dialogue 9:16: title on top, the subtitle band above the portraits at the
  bottom; long lines wrap to two lines inside the band. One cosmetic nit: the
  last line wraps as `…足せる` / `よ！`, leaving `よ！` alone.

`--json` on the ranking project reported `"propsFile": …/props.json` and
`"propsFileAuto": true`. The scratch folder was removed afterwards.
